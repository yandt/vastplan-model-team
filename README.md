# VastPlan · 多模型团队归档

把**真实工程**里的多模型表现按周归档。不是题库、不是合成任务，就是 VastPlan（自研 Node/TypeScript 插件运行时与 Portal 内核）日常开发流程里跑出来的账。

评测分两部分：

- **事后审计**：一段功能代码写完、自测通过后，多家模型并行审，找 BUG、提优化点。每条意见逐条对照代码判定成立/不成立，成立的按 1~5 记严重度，假阳性如实记账。
- **设计分叉**：遇到有多种合理走法的设计题，各模型各自出方案；等项目里真实选定之后，再回头算每家方向的契合度。

## 目录约定

```
<类型>/<周期>/               # 类型目前只有 weekly；周期形如 2026-09-07_2026-09-14
├── report.html             # 报告（图表版，顶部有回到本目录的链接）
├── report.md               # 同一份内容的纯文本
├── post.md                 # 由模型写的中文发帖稿（含生成模型、耗时、金额）
├── summary.json            # 该周期的机器可读摘要（含生成次数与时间）
└── images/*.png            # 16:9 配图（2400×1350），切自报告版块
```

**一个周期一个目录**：同一周期再次生成会覆盖该目录内容，所以每周只有一条记录，跨周看趋势不会被同周的多次生成搅乱。
被覆盖的旧版本不丢——`git log --follow weekly/<周期>/report.html` 能看到历史。`summary.json` 里的 `generations` /
`first_generated_at` / `last_generated_at` 是将来画趋势图的数据源。

## 综合能力评分

`0~100 = 30% 产出（均质量） + 25% 精准（成立/(成立+假阳)） + 20% 独立（独有/成立） + 25% 性价比（效率分）`

同一活动类型内各项 min-max 归一到 0~100 后加权。**这是相对排名，不是绝对能力分**——换一批模型进来，分数会动。

各子分项各自排名，不混：产出（平均质量分）、精准（准确率）、独立（独有占比）、性价比（效率分）、执行时间（平均每次分钟）、每条成立 token（千枚）、缓存命中率（越高越省）、成立密度（每次，越多越好）、每次花费（越低越省）。成立严重度是整场堆叠条，不做模型排名。

**计数类指标一律折成「每次已评运行」再比**：成立数、花费、假阳都会随样本量涨，各模型场次不同时直接比总数会误导。报告表里的成立/独有/假阳仍是本周合计，看总数请对照「场」列。

## 口径与局限

- 失败（退出码非 0 / 超时）与未经逐条判定的场次**不进对照**，花费照计。
- 订阅制模型没有公开 API 牌价时，金额记「未采集」，不记 0。
- 样本 < 20 场标 `※`，结论打折；表下另给「主力（≥20 场）第一」。
- 覆盖的模型随周变化，历史各周的名单以该周报告为准。
- 执行时间＝已评行耗时合计 ÷ 已评运行次数；token＝输入+输出+缓存读+缓存写；每条成立 token＝token ÷ 成立数；缓存命中率＝缓存读 ÷（输入+缓存读）。未评与失败行没有耗时数据，只计花费。

## 怎么生成

由主仓 `VastPlan@Node` 的 `model-team` 技能一条命令产出（报告两版 + 配图 + 发帖稿），本仓只是归档落点。
